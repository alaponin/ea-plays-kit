# The register of requirements — the allotment registry (fixture)

*A fixture: the stand-in for the register a real model binds to, published in its own row of
the specification tree. Every entry is fictitious and is realised by at least one use case of
the fixture's model, so that the binding closes in both directions.*

| Identifier | The requirement |
|---|---|
| FR-APP-001 | A resident can apply for a plot while the application window is open |
| FR-APP-002 | The registry confirms who is applying before it accepts an application |
| FR-APP-003 | The registry confirms that the applicant lives in the town |
| FR-SEA-001 | The application window opens and closes on the season's calendar |
| FR-ALC-001 | The garden officer allocates free plots to accepted applications |
| FR-ALC-002 | Every allocation decision is recorded with its reason |
| FR-ALC-003 | An applicant who cannot be given a plot is placed on the waiting list |
| FR-PAY-001 | The plot rent is paid before the plot is handed over |
| FR-REL-001 | A resident can give a plot up during the season |
| QR-AUD-001 | Any allocation can be explained afterwards from the registry's own record |
| CON-DAT-001 | Residence data is read from the address register and never kept twice |
