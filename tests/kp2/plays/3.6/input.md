**Produces:** B19 — Change control, standards register (with conformance fields) and semantic-registry charter

## What the learner types

Draft three things for [country X]'s Government Interoperability Framework so governance stays a living configuration. (1) A CHANGE-CONTROL PROCESS for changes to the live framework — covering, for each change type (admit a member; update or retire a standard; authorise a new exchange; change the security model): who proposes, who reviews, who is Accountable for the decision (reference the RACI), how it is recorded, and how it is communicated to members. Keep it lightweight — a process so heavy no one follows it is worse than none. (2) A STANDARDS-PORTFOLIO REGISTER template — the columns needed to track each current standard: name, version, status (current/deprecated), binding date, transition period for legacy systems, conformance-test approach (self-assessment / third-party / test suite), re-certification cycle, owner Working Group, exceptions granted, last reviewed. Name the role (inside the Operating Authority) that maintains it. (3) A SEMANTIC-REGISTRY CHARTER — one paragraph: what it holds (data dictionary, code lists, cross-walks between sector vocabularies, aligned to ISO/IEC 11179), who stewards it (the operator) and who owns the entries (sector data owners). the change-control process and the register template.
