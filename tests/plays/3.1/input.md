# Play 3.1 — Design your EA repository's structure · fixture input

**Consumes:** A13 — from [`tests/progressa.md`](../../progressa.md).
**Primary skill:** `ea-governance-drafter`
**Produces:** A16 — EA repository structure

## What the learner types

I am setting up an EA repository for [country X]'s [sector] sector, starting in [a spreadsheet / a wiki / a dedicated tool]. I have a four-layer picture with [briefly: how many capabilities, data domains, applications you have captured]. Design the repository structure. Produce: (1) the sections/tabs it should have — at least Capabilities, Data Domains (with one named owner each), Applications (mapped to capabilities and data domains), Technology, and a Decision Log; (2) for each section, the fields it should capture; (3) the relationships to record between sections, using the PAERA metamodel entities; (4) the single-source rules — who may edit, how a change is recorded, how you prevent second copies. Output: a section-by-section schema plus a short 'single-source rules' list.

## What the fixture supplies

Country: **Progressa** · Sector: **Education**. Substitute for every bracketed
placeholder above. The named input is A13 of `tests/progressa.md`; paste
those sections verbatim.

Where the play consumes an artefact from an earlier play (A1, A3, A22 …), run that
play on Progressa first — the chain is in
[`shared/workbook-chain.md`](../../../plugins/ea-plays/shared/workbook-chain.md).
